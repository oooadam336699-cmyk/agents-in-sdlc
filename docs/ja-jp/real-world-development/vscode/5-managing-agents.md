GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。作業は自分のマシンでリアルタイムに進むため、VS Code の Copilot Chat ではツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を採用または取り消し、エディターを離れずに追加のプロンプトを送って作業を調整できます。

このレッスンでは、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- 作業中のセッションに指示を追加し、ハイ コントラスト モードとともにライト モードの切り替えを追加します。

## シナリオ

[レッスン 4][previous-lesson]で使ったアクセシビリティのカスタム エージェントが、ハイ コントラスト モードを実装しています。作業中、デザイン チームから追加の要望がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加してほしいとのことです。新しい会話を始める代わりに、現在のセッションに追加の作業を依頼します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。確認したファイル、実行したコマンド、提案した編集を確認できます。各ファイルの差分には **Keep** と **Undo** の操作が表示されます。

1. レッスン 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、インラインで差分が表示されます。
   - **Keep** を選択して変更を採用します。
   - **Undo** を選択して変更を取り消し、もう一度作業するよう依頼します。
4. チャット上部の **Files changed** の表示を開くと、セッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ターミナル コマンドの実行などで許可が必要な場合、エージェントは一時停止し **Allow** を表示します。内容を確認し、問題のないコマンドだけを許可してください。

5. エージェントがハイ コントラスト モードを実装し終えるまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## ライト モードを追加するようエージェントに指示する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えを追加します。同じチャット セッションを続けることで、エージェントは変更したコンポーネント、採用したスタイル、設定したローカル ストレージのパターンなど、前の作業のコンテキストを保てます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を調べ、ライト モードの追加を提案します。
3. ハイ コントラスト モードと同じように、新しい編集を確認します。それぞれの差分に対して **Keep** または **Undo** を選択します。
4. エージェントが期待と異なる方向に進んだ場合（たとえば、好ましくない方法でトグル UI をリファクタリングしようとした場合）は、チャット入力欄の隣にある **Stop** ボタンで停止し、説明を加えたプロンプトを送ります。

> [!TIP]
> 進行中のセッションに追加の指示を送ると、最初からやり直すより早く修正できます。「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」のような調整、「3 つ目のトグルは追加せず、既存の設定パネルにライト モードを統合する」のような方向修正、「両方のトグルにキーボード ショートカットも追加する」のような範囲の拡張を依頼できます。

## 変更されたファイルを確認する

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントのアクセシビリティ方針が反映されているか、ARIA 属性、キーボード操作、セマンティック HTML、ローカル ストレージによる設定保持などを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して方向を伝えました。ファイル編集が反映されるたびにレビューし、変更を採用または取り消し、コンテキストを保ちながら追加プロンプトを送って作業を拡張しました。

このレッスンでは、次のことを学びました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を採用または取り消す。
- 追加プロンプトを使って、進行中のセッションに指示を送る。

次の[レッスン][next-lesson]では、アクセシビリティ機能をプルリクエストとして公開し、このラボを通じてローカル カスタム エージェントが作成した変更をレビューします。
